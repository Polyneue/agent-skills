# Review Pull Request

This skill automates reviewing GitHub Pull Requests by inspecting the PR metadata and diff using the GitHub CLI (`gh`), formatting structured inline line comments and an overall review summary body, and submitting the batch PR review with a review event (`COMMENT`, `APPROVE`, `REQUEST_CHANGES`) using the GitHub REST API via `gh api`.

## Workflow

### 1. Inspect GitHub CLI and Repository Context
- Verify that `gh` CLI is installed and authenticated:
  ```bash
  gh auth status
  ```
- Verify git repository context and remote details:
  ```bash
  gh repo view --json nameWithOwner,defaultBranchRef,name,owner
  ```

### 2. Identify Target PR and Fetch Context
- If a PR number or URL is specified by the user, extract the `<number>`.
- If no target PR is specified, check if the current branch has an associated PR or list open PRs:
  ```bash
  # Check active branch PR
  gh pr view --json number,title,headRefName,baseRefName,url,state
  ```
  Or list open PRs:
  ```bash
  gh pr list --json number,title,headRefName,author,updatedAt --limit 10
  ```
- Fetch full PR details and diff:
  ```bash
  gh pr view <number> --json number,title,body,headRefName,baseRefName,author,url,files,commits
  gh pr diff <number>
  ```

### 3. Analyze PR Changes and Formulate Review Feedback
- Review the PR description, list of changed files (`files`), commit history, and code diff output (`gh pr diff <number>`).
- For each piece of feedback:
  - Determine whether it applies to the PR overall (general review body) or a specific line of code in a modified file (inline comment).
  - For inline comments, identify:
    - **`path`**: Exact relative file path as shown in the PR diff.
    - **`line`**: The 1-based target line number in the modified file.
    - **`side`**: `RIGHT` for lines in the new version of the file (additions/unmodified lines in diff), `LEFT` for deleted lines in the old version. Default is `RIGHT`.
    - **`body`**: Clear, constructive inline feedback text.
- Determine the overall review decision / event:
  - **`APPROVE`**: Submit an approval when changes are clean, correct, tested, and meet guidelines.
  - **`REQUEST_CHANGES`**: Request changes when there are blocking bugs, security concerns, or critical flaws requiring edits.
  - **`COMMENT`**: Submit general feedback or non-blocking suggestions without explicit approval/rejection.

### 4. Construct Structured Review Payload
- Assemble the payload JSON according to GitHub's REST API endpoint requirements (`POST /repos/{owner}/{repo}/pulls/{pull_number}/reviews`):
  ```json
  {
    "body": "<Overall review summary string>",
    "event": "COMMENT",
    "comments": [
      {
        "path": "src/index.ts",
        "line": 45,
        "side": "RIGHT",
        "body": "Consider adding error handling here for empty inputs.\n\n---\n\n_Inline comment generated by Antigravity_"
      }
    ]
  }
  ```
- **Attribution Requirement**:
  - Always append an AI attribution footer to the overall review `body` separated by a horizontal rule (`---`):
    ```markdown
    ---
    *Review submitted by Antigravity.*
    ```
  - For individual inline comments, append an inline attribution footer:
    ```markdown

    ---
    _Inline comment generated by Antigravity_
    ```
  *(Or replace `Antigravity` with the current agent name if executing under a different context).*

### 5. Submit Review via GitHub CLI (`gh api`)
- Save the structured payload JSON to scratch space (`<appDataDir>/brain/<conversation-id>/scratch/pr_review_payload_<number>.json`).
- Submit the review using `gh api`:
  ```bash
  gh api \
    --method POST \
    -H "Accept: application/vnd.github+json" \
    /repos/<owner>/<repo>/pulls/<pr_number>/reviews \
    --input "<path_to_scratch>/pr_review_payload.json"
  ```
- **Note on Empty Comments**: If there are no inline comments (only overall feedback), the `"comments"` array can be omitted or set to `[]`.

### 6. Verify and Report Results
- Verify successful API response (HTTP 200/201). The response contains the review ID and `html_url`.
- Present a Markdown summary report to the user:
  - **PR Link**: Markdown link to the PR `[#<number>: <title>](<pr_url>)`.
  - **Review Event**: Decision submitted (`APPROVE`, `REQUEST_CHANGES`, or `COMMENT`).
  - **Summary**: Highlights of the review summary body.
  - **Inline Comments Table**:
    | File | Line | Side | Comment Summary |
    | :--- | :--- | :--- | :--- |
    | `<path>` | `<line>` | `RIGHT` / `LEFT` | `<truncated_comment_body>` |

## Example CLI Commands & API Payload

### Fetch PR Context & Diff
```bash
gh pr view 42 --json number,title,url,files
gh pr diff 42
```

### Save Review Payload (`scratch/pr_review_payload.json`)
```json
{
  "body": "## PR Review Summary\n\nOverall the implementation looks solid. A few minor suggestions noted inline regarding error handling and variable naming.\n\n---\n*Review submitted by Antigravity.*",
  "event": "COMMENT",
  "comments": [
    {
      "path": "src/utils.ts",
      "line": 32,
      "side": "RIGHT",
      "body": "Ensure null checks are performed before accessing properties here.\n\n---\n_Inline comment generated by Antigravity_"
    }
  ]
}
```

### Submit Review Call
```bash
gh api \
  --method POST \
  -H "Accept: application/vnd.github+json" \
  /repos/Polyneue/agent-skills/pulls/42/reviews \
  --input scratch/pr_review_payload.json
```
