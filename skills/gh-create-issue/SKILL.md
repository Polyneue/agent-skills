# Create GitHub Issue

This skill automates discovering repository issue templates, resolving ambiguous or underspecified user inputs using `ask_question`, structuring issue titles and bodies according to matched templates, and submitting issues using the GitHub CLI (`gh`).

## Workflow

### 1. Inspect GitHub CLI and Repository Context
- Verify that `gh` CLI is available and authenticated: `gh auth status`.
- Verify git repository context and remote details: `gh repo view --json nameWithOwner,defaultBranchRef`.

### 2. Discover and Select Issue Template
- Check for existing issue templates in the following order of precedence:
  1. `.github/ISSUE_TEMPLATE/` directory (e.g., `bug_report.md`, `feature_request.md`, `custom.md`, or YAML forms `bug_report.yml`/`yaml`).
  2. `.github/ISSUE_TEMPLATE.md`
  3. `.github/issue_template.md`
  4. `ISSUE_TEMPLATE.md`
- List and inspect template files using `list_dir` and `view_file`.
- Match the user's intent to the appropriate template:
  - **Bug Report**: Look for templates containing `bug`, `defect`, `problem`, `error`.
  - **Feature Request**: Look for templates containing `feature`, `enhancement`, `request`, `proposal`.
  - **Task / Documentation**: Look for templates containing `task`, `docs`, `documentation`, `chore`.
  - **Custom / Default**: If multiple templates exist, choose the best semantic match. If no template exists, proceed with standard issue structure.

### 3. Parse Template Metadata and Fields
- Parse YAML frontmatter metadata if present (between leading `---` blocks in markdown templates or native `.yml`/`.yaml` issue forms):
  - `name`: Human-readable template name.
  - `about`: Template description.
  - `title`: Default issue title prefix or template (e.g., `[BUG]: ` or `[FEAT]: `).
  - `labels`: Array or comma-separated list of default labels (e.g., `bug`, `triage`, `enhancement`).
  - `assignees`: Default assignees.
  - `projects`: Associated project boards.
- Extract form fields, headers (`## Describe the bug`, `## Expected Behavior`, `## Environment`), and comment placeholders (`<!-- ... -->`).

### 4. Interactive Ambiguity Resolution (`ask_question`)
- Detect missing, incomplete, or ambiguous issue details prior to drafting:
  - **Ambiguous Scope / Description**: If the user prompt is broad or lacks reproduction steps, acceptance criteria, or context.
  - **Template Selection**: If multiple issue templates match the intent equally well.
  - **Metadata & Labels**: If labels, assignees, or component scopes are unspecified or ambiguous.
- Use `ask_question` to present structured choices to the user:
  - Structure concise, informative questions resolving specific ambiguities (e.g. title prefix preference, component tags, issue priority).
  - Provide at least 2 clear response options per question, formatted as direct user responses (e.g., `"[FEAT] Add interactive question prompting to gh-create-issue"` vs `"[ENHANCEMENT] Support ask_question in gh-create-issue"`).
  - Use `is_multi_select: true` when allowing selection of multiple labels or options.
- Integrate user responses directly into the template parameters, issue fields, labels, and body draft before proceeding.

### 5. Draft Title and Populate Issue Body
- **Title**: Use the template's title prefix (if provided in frontmatter or selected via `ask_question`) combined with a clear, concise summary of the issue.
- **Body**: Fill out each section of the template cleanly based on user details, `ask_question` clarifications, and codebase findings:
  - Fill out mandatory sections (reproduction steps, expected/actual behavior, context, logs).
  - Remove unneeded comments (`<!-- ... -->`) and empty placeholder markers (`[Describe what happened here]`).
  - If a template is unavailable, structure the issue cleanly with:
    - **Description**: High-level overview of the issue or feature request.
    - **Steps to Reproduce / Details**: Context or reproduction steps.
    - **Expected Outcome**: What should happen.
    - **Environment / Context**: Relevant system details, OS, version, stack traces, or logs.
- **Attribution**: ALWAYS append the following footer at the bottom of the issue body:
  ```markdown
  ---
  *Issue generated by Antigravity.*
  ```

### 6. Create Issue via GitHub CLI (`gh`)
- Save the drafted issue body to a temporary markdown file in scratch space (`<appDataDir>/brain/<conversation-id>/scratch/issue_body.md`) to prevent shell escaping or quoting issues.
- Build the `gh issue create` command incorporating flags extracted from template frontmatter, user prompt, or `ask_question` responses:
  ```bash
  gh issue create \
    --title "<Title>" \
    --body-file "<Path to issue_body.md>" \
    [--label "<label1>,<label2>"] \
    [--assignee "<user>"] \
    [--project "<project>"]
  ```

### 7. Return Result to User
- Provide a concise summary of the created issue (Issue number, Title, Labels, Assignees).
- Output a direct markdown link to the newly created issue URL (e.g., `[Issue #42](https://github.com/owner/repo/issues/42)`).

## Example Template, Interaction & Output

### Input Template (`.github/ISSUE_TEMPLATE/bug_report.md`):
```markdown
---
name: Bug report
about: Create a report to help us improve
title: '[BUG] '
labels: 'bug, needs-triage'
assignees: ''
---

## Describe the bug
A clear and concise description of what the bug is.

## To Reproduce
Steps to reproduce the behavior:
1. Go to '...'
2. Click on '...'
3. Scroll down to '...'
4. See error

## Expected behavior
A clear and concise description of what you expected to happen.

## Context & Logs
Add any other context or logs about the problem here.
```

### `ask_question` Tool Call (Ambiguity Resolution):
```json
{
  "questions": [
    {
      "question": "Which label(s) should be applied to this bug report?",
      "options": [
        "bug, high-priority",
        "bug, needs-triage",
        "bug, documentation"
      ],
      "is_multi_select": false
    }
  ]
}
```

### Generated Command:
```bash
gh issue create --title "[BUG] Router panics on invalid UTF-8 query params" --body-file "/path/to/scratch/issue_body.md" --label "bug, needs-triage"
```
